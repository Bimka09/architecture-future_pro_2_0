## Ключевые изменения

| Компонент                       | Изменение                                                                                                                          |
|---------------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| **DWH (SQL Server 2008)**       | Заменяется на **Modern DWH** (Snowflake/BigQuery) в облаке. Используется как аналитическая витрина, а не центр бизнес-логики.      |
| **PowerBuilder UI**             | Сохраняется временно через **Legacy Bridge**, планируется постепенная замена на облачные приложения.                               |
| **ESB (Apache Camel)**          | Трансформируется в **Anti-Corruption Layer** + **Legacy Bridge**. Основная интеграция — через **event-driven streaming platform**. |
| **Новая платформа**             | Вводится **Data Mesh** с доменными Data Products, что позволяет каждому подразделению управлять своими данными независимо.         |
| **BI-система**                  | Power BI остаётся, но подключается к Modern DWH и Data Product API, а не напрямую к легаси-DWH.                                    |
| **Обработка данных**            | Переход от batch ETL к **near-real-time stream processing** (Kafka + Flink/Spark).                                                 |
| **Безопасность и соответствие** | Внедряются политики RBAC, шифрование, аудит, соответствие GDPR/HIPAA через cloud-native tools.                                     |

План миграции логики ESB на другие компоненты:
1. Сначала идут компоненты API Gateway и Service Mesh, которые будут выполнять функции маршрутизации и управления доступом. С их помощью можно будет разграничивать трафик между легаси системой и новыми сервисами.
2. Далее нужно по одному выделять доменные сервисы, в которые перейдет частично логика из легаси системы. В доменных сервисах нужно предусмотреть интеграцию посредством передачи Protobuf сообщений. Необходимо применение паттернов распределенных систем.
3. Транспортный уровень по передаче сообщений ляжет на Apache Kafka
4. Когда новые сервисы будут запускаться в работу нужно настроить на ESB логику, которая будет вычитывать сообщения из Kafka и записывать в легаси систему, таким образом мы сможем поддержать бекпортинг и оставить легаси систему консистетной до момента перехода полностью на новую архитектуру.
5. Трансформации будут реализованы с помощью Apache Airflow для получения данных по аналитике из новых сервисов
6. Для интеграций внешних сервисов в нашу нужно реализовать API и асинхронный обмен событиями.
