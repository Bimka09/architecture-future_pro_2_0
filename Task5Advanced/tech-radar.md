# Расширенный технический радар

Технический радар охватывает не только технологии, но и архитектурные подходы, такие как Data Mesh, Event-Driven
Architecture и Self-service BI. Каждая технология или паттерн оценены по следующим категориям:

- **Категория**: Data Platform, Analytics, Integration, Security, Governance, Development.
- **Статус**:
    - **Adopt** — рекомендовано к активному использованию.
    - **Trial** — прототипирование в пилотных доменах.
    - **Assess** — требуется исследование.
    - **Hold** — заморожено, не рекомендуется к новому использованию.
- **Обоснование** — краткое описание причин выбора статуса.

## Категории

- **Data Platform** — технологии хранения, обработки и управления данными.
- **Analytics** — инструменты анализа данных.
- **Integration** — решения для интеграции систем.
- **Architecture** — архитектурные подходы.
- **Governance** — технологии управления данными, метаданными, качеством и lineage.
- **Security** — обеспечение безопасности данных.
- **Orchestration** — инструменты управления рабочими процессами.
- **Development** — инструменты разработки и DevOps.

## Статусы

| Статус     | Описание                                                                                  |
|------------|-------------------------------------------------------------------------------------------|
| **Adopt**  | Активно используется или стратегически внедряется в рамках целевой архитектуры.           |
| **Trial**  | Тестируется в пилотных доменах. Готово к масштабированию при успехе.                      |
| **Assess** | Перспективная технология, требует исследования и Proof of Concept (PoC).                  |
| **Hold**   | Используется в легаси-системах, но не допускается в новых проектах. Планируется миграция. |

## Технический радар

### Architecture

| Технология / Паттерн       | Статус | Обоснование                                                                                                                                      |
|----------------------------|--------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| Data Mesh                  | Assess | Не используется. Перспективный паттерн для масштабирования. Требует PoC и организационных изменений.                                             |
| Event-Driven Architecture  | Trial  | Частично реализована через CDC и Kafka в пилоте финтех-домена. Не повсеместна.                                                                   |
| Microservices              | Adopt  | Некоторые сервисы на Golang/Java построены как микросервисы, но большинство бизнес-логики — в DWH. Архитектурный стиль необходимо внедрять шире. |
| Domain-Driven Design (DDD) | Assess | Не применяется. Границы доменов не формализованы. Требуется при переходе к Data Mesh.                                                            |
| API-First Design           | Trial  | Используется в новых финтех-сервисах, но не стандартизировано.                                                                                   |

### Data Platform

| Технология / Паттерн        | Статус | Обоснование                                                                                                     |
|-----------------------------|--------|-----------------------------------------------------------------------------------------------------------------|
| Delta Lake                  | Assess | Не используется. Рассматривается как кандидат для облачного хранения.                                           |
| Iceberg                     | Assess | Не используется. Исследуется как альтернатива.                                                                  |
| Snowflake                   | Assess | Не используется. Оценивается в рамках миграции в облако.                                                        |
| Databricks                  | Assess | Не используется. Потенциальный кандидат для ML и аналитики.                                                     |
| AWS S3 / Azure Blob Storage | Trial  | Используется в пилотной среде для загрузки данных из DWH.                                                       |
| SQL Server 2008             | Hold   | Основа DWH в текущей системе. Используется повсеместно. Запрещён в новых проектах. Планируется миграция данных. |

### Analytics

| Технология / Паттерн | Статус | Обоснование                                                                              |
|----------------------|--------|------------------------------------------------------------------------------------------|
| Self-service BI      | Assess | Не реализовано. Рассматривается как цель трансформации.                                  |
| Apache Superset      | Assess | Не используется. Рассматривается как замена Power BI.                                    |
| Power BI             | Hold   | Широко используется, но с множеством кастомизаций и зависимостью от DWH. Не развивается. |
| Real-time Analytics  | Assess | Не реализовано. Все отчёты — batch. Исследуется Flink/Kafka.                             |

### Integration

| Технология / Паттерн      | Статус | Обоснование                                                                                           |
|---------------------------|--------|-------------------------------------------------------------------------------------------------------|
| Apache Kafka              | Adopt  | Внедряется в пилоте финтех-домена. Пока не центральная шина, но нет сомнений в надежности технологии. |
| REST API                  | Adopt  | Используется в ИИ- и финтех-сервисах. Основной способ взаимодействия между сервисами.                 |
| gRPC                      | Assess | Не используется. Исследуется потенциал для улучшения производительности сервисов.                     |
| Camel (ESB)               | Hold   | Активно используется как интеграционная шина. Планируется постепенная замена.                         |
| Change Data Capture (CDC) | Assess | Исследовать потенциал использования Debezium для репликации из SQL Server в Kafka.                    |

### Orchestration

| Технология / Паттерн | Статус | Обоснование                                               |
|----------------------|--------|-----------------------------------------------------------|
| Apache Airflow       | Assess | Не используется. Планируется как оркестратор для ETL/ELT. |
| Prefect              | Assess | Не используется. Альтернатива Airflow.                    |
| Dagster              | Assess | Не используется. Перспективен, но требует исследования.   |

### Governance

| Технология / Паттерн   | Статус | Обоснование                                                      |
|------------------------|--------|------------------------------------------------------------------|
| Data Catalog           | Assess | Не существует. Планируется как часть Data Mesh.                  |
| AWS Glue Data Catalog  | Assess | Не используется. Возможный кандидат в облаке.                    |
| Apache Atlas           | Assess | Не используется. Требует настройки и интеграции.                 |
| Data Contract          | Assess | Не используется. Планируется как элемент SLA для data products.  |
| Data Quality Framework | Assess | Качество данных обеспечивается вручную. Инструменты не внедрены. |

### Security

| Технология / Паттерн                  | Статус | Обоснование                                                     |
|---------------------------------------|--------|-----------------------------------------------------------------|
| Role-Based Access Control (RBAC)      | Hold   | Реализован в PowerBuilder и Power BI, но не централизованно.    |
| Attribute-Based Access Control (ABAC) | Assess | Не используется. Перспективно для гибкого контроля доступа.     |
| Data Masking                          | Hold   | Применяется выборочно в тестовых средах. Нет единой политики.   |
| Audit Logging                         | Hold   | Логирование есть, но фрагментарно. Нет централизованного сбора. |

### Development

| Технология / Паттерн         | Статус | Обоснование                                                               |
|------------------------------|--------|---------------------------------------------------------------------------|
| GitOps for Data Pipelines    | Assess | Не используется. Планируется при внедрении CI/CD.                         |
| Infrastructure as Code (IaC) | Assess | Terraform/Pulumi не используются. Ручное развёртывание.                   |
| CI/CD для Data Products      | Assess | Нет автоматизации. Все изменения — вручную.                               |
| Python (Pandas, PySpark)     | Adopt  | Используется в ИИ-сервисах и скриптах обработки. Основной язык аналитики. |
| dbt (data build tool)        | Assess | Не используется. Рассматривается для ELT.                                 |
